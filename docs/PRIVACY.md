# CNrecipe privacy disclosure draft — local user data, 2026-11-01

CNrecipe keeps ingredients, shopping lists, preferences, favorites, cooking history and an active cooking session on your device. The current product mode has no sign-in or account-sync entry, does not automatically restore an earlier Supabase session, and does not upload those user records. Core saved content is available offline. This is the current implementation disclosure target; the [2026-11-01 local-mode delivery report](../artifacts/local-first-20261101/report.md) records the actual tests performed on the build. The 2026-10-31 migration report is historical evidence.

The client still contacts the independent CNrecipe Supabase project in Singapore for the public recipe catalog, search, server-generated portion/unit projections and recipe images. Search text entered by the user is sent to the public recipe API. Inventory names and selected allergen preferences are matched or annotated locally rather than attached to each catalog request. Recipe and storage guidance is illustrative and is not a food-safety measurement or a medical diagnosis.

Existing account-cache files and Keychain items are preserved separately. They are not automatically merged into the device kitchen or used as a current signed-in session. Earlier Supabase Auth, sync and RLS work is retained for a future optional synchronization feature. That work, including the recent Magic Link integration, has not passed real email-return and two-device acceptance; the previously authorized test email was not sent. No current recovery promise should be inferred from the retained code.

The current source has no advertising, analytics SDK, tracking SDK or remote AI service. Public API and image requests can produce operational metadata at Supabase. The publisher must verify the provider's settings, access and retention before publishing a user-facing privacy policy. The app must not be described as fully network-free merely because its user records stay local.

Timer notifications are optional. Permission is requested when starting a timer; refusal leaves the in-app timer usable. Resetting the device kitchen creates a local recovery backup before replacing active device data. Original migration files and recovery backups remain on the device. These local files do not establish a tested iCloud backup, device-transfer or reinstall recovery feature. Device loss, replacement or App removal can make local data unavailable; Keychain removal must not be assumed to follow App removal.

This document is an implementation inventory, not a published legal policy. Six recipe images have been uploaded and downloaded with matching SHA-256 checksums. Remaining visual, platform and content-review limitations are listed in the [current local-mode delivery report](../artifacts/local-first-20261101/report.md). Publishing still requires publisher identity, support contact, a hosted privacy-policy URL, provider/retention review and App Store disclosures matching the actual signed binary. Signing, archive and TestFlight remain paused by user instruction.

Optional Supabase Auth synchronization may be reopened only when users need device replacement recovery or multi-device sync. Before it is exposed, the project must complete reliable SMTP delivery, real two-device tests, account deletion, a published privacy policy and a data-lifecycle explanation covering local import, synchronization, retention, logs, backups, deletion and recovery. These are reopening requirements for the optional feature; unfinished login is not a prerequisite for using the current local recipe experience. Retaining Supabase Auth avoids a service migration and does not by itself satisfy any of these requirements.
