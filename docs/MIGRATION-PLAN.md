# CNrecipe 统一 API 与混合原生迁移

## 目标与确认事实

当前执行：2026-10-31 用户确认的架构迁移及全页面优化，并按 2026-11-01 最新决定收敛登录范围。SwiftUI 原生导航与功能页，Explore 保留 Web；Supabase 继续管理菜谱 API、图片和数据库。当前核心体验无需账号，登录与账号同步入口隐藏，全部用户实体保存在本机；同步留作未来可选功能。不是把现有整套 WebView 宣称为原生。

迁移前实际实现：SwiftUI Shell + 整套 WKWebView，六道菜谱写在 HTML 数组，version 1 本地 JSON 保存用户数据。无服务端数据库、登录及同步。

ZIP 与 `docs/design-handoff-2026-10-31/` 中全部文件逐字节一致。规范优先级：本次用户架构指令 > ZIP 明确的业务/组件规则 > SVG 原稿 > 位图示例。ZIP 第 7 节保留旧架构及不新增云端的限制被本次迁移授权替代；页面结构、颜色、字体、图标与动效继续适用。

## 约束

- 三个主入口 Explore / My Kitchen / Saved；任务页无底部主导航。不新增 Profile 或第四 Tab。
- 保留显式保存烹饪历史；未点击保存离开完成页不自动新增历史。
- 采用 ZIP 原有食品/设备 SVG，不把示例白胡椒、特殊锅型、备注字数限制、收藏行额外按钮加入产品。
- 各类数量和日期由实际数据计算；不复制位图示例数据。
- 现有六道菜谱作为标注 demo 的种子，继续使用已生成的六张图；不宣称内容已经烹饪审核。
- 原始参考 HTML 不改。原子本地写入、错误保护、重置备份保留。迁移保留原文件及校验，失败不覆盖。
- 不操作 iPhone Duo `258237B2-5A7B-46C2-9562-99ED8C4482A8`。不做真机、Personal Team、archive、TestFlight 或正式发布。
- 现有 SelfForge Supabase 项目无关且暂停，不复用、不修改。继续使用独立 CNrecipe 项目与新加坡区域。Supabase Auth、同步和 RLS 保留，不为暂缓登录更换服务。
- 当前不开放登录，不自动恢复旧会话或上传用户数据；已有账号缓存和 Keychain 项保留，不删除、不擅自合并到设备数据。此前授权的一封登录测试邮件未发送，本轮不继续发送。

## 实施顺序与验收门槛

1. **基线与契约**：保存全部源码及用户数据的只读备份；固定菜谱/食材/步骤 ID、内容版本、API、用户操作、同步冲突与离线规则；建立 ZIP 逐项矩阵。
2. **统一数据库与业务 API**：菜谱与内容版本、所有权隔离、库存匹配、份数/单位换算、购物清单合并、带幂等键的同步；六道种子及图片存储清单；构建实际数据库与 HTTP 自动验证。
3. **Explore Web**：从整套 HTML 拆出发现与搜索，接入 API；菜谱链接打开原生详情，独立浏览器有 Web 详情回退；受限桥接、主框架与来源校验，凭证不进入 Web JS。
4. **原生页面**：详情、备料、Cook、完成、库存、购物、Saved 子页、设置及表单；原生导航与系统输入控件；逐页按 ZIP 对照。
5. **当前本地持久化**：旧版数据保留与迁移、设备本地原子存储、冷启动与离线恢复；烹饪会话持有不可变菜谱版本快照。现有账号会话、同步队列与冲突处理实现保留为后续可选同步基础，不作为当前用户数据上传路径。
6. **验收与交付**：数据库/公共 API 集成、Web 浏览器、原生领域及 UI、无需账号的本地增删改/重启/离线/历史/计时竞态/减少动态效果；Debug 与 Release Simulator 构建；同尺寸视觉对照与录屏；保存所有结果及未验证项，更新运行入口。登录与同步的未来门槛见下文。

Android 和独立桌面客户端本轮不另建工程；为其提供同一 API 契约和可独立访问的 Explore Web。

## 数据与离线边界

- 云端权威：菜谱、标准食材、步骤、图片、内容版本及公开用量投影；继续由现有 Supabase 数据库与 API 提供。
- 当前用户数据权威：本机的库存、收藏、购物清单、偏好、历史、计时器和当前烹饪状态。云端用户表/RLS 保留，但当前 App 不调用用户同步。
- 客户端：展示、系统能力、公共内容缓存、本地用户数据、即时计时与当前操作状态。搜索文字仍发送公共 API；库存名称和过敏偏好在本地匹配/标注，不随每次目录请求上传。
- 烹饪开始时冻结完整菜谱版本及用量响应，后台内容更新不替换正在执行的步骤。
- 设备数据与历史账号缓存分隔；不自动使用或合并历史账号数据。本地恢复备份不等于已验证的 iCloud、换机或卸载恢复能力。
- 未来同步的操作 UUID、版本检查、重试幂等、服务端墓碑和冲突保留规则继续保留，开放前须重新端到端验证。
- 离线不声称公共目录和推荐已实时更新；使用已下载内容。离线换算使用服务端已生成的用量投影，不在各平台另写换算规则。

## 未来开放可选同步的门槛

只有后续用户确实提出换机丢数据或多设备同步需求时，再安排 Supabase Auth 登录开放。继续使用现有 Supabase Auth、同步和 RLS，无须更换服务。开放前必须全部完成：

1. 可靠 SMTP 与真实投递、重发、过期、错误及限流验证。
2. 同账号真实双设备的创建/编辑/删除、离线恢复、冲突及退出/换号隔离测试。
3. 可用的账号删除流程与云端/本地处置验证。
4. 已发布的隐私政策、支持联系入口与对应实际发布版本的数据披露。
5. 数据生命周期说明：本地导入、保存时长、同步、日志、备份、注销/删除及恢复规则。

不能仅翻开登录入口或配置开关视为达成。此前 PKCE/Magic Link 工作未验收，不能以半途代码或保留的服务端契约替代这些门槛。
